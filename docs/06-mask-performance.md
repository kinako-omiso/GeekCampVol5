# Issue #2：マスク表示時間の検証

## 目標と測定区間

対象の指定を終えてからマスクが画面に表示されるまでを1,500ms以内にする。
写真選択時の画像読み込み、モデル初期化、`setImage()`は別に測定する。

画面の「Mask表示」は、`pointerup`から推論・マスク変換・描画を経て、描画後に実行するコールバックまでの推定時間。ディスプレイへの実際の表示時刻を直接測った値ではない。

## 2026-09-27の検証結果

- 対象：Issue #2の`/dev/photo-model`。
- ライブラリ：`@mediapipe/tasks-vision` 1.0.1。
- モデル：同梱のInteractive Segmenter v2 / MagicTouch int8。
- 環境：Windows Chromeのヘッドレス実行、一時プロファイル、前面タブ。
- WebGLレンダラー：ANGLE / NVIDIA GeForce RTX 4060 Ti / Direct3D11。
- 入力：[Google公開の猫の検証画像](https://storage.googleapis.com/mediapipe-assets/cat.jpg)（600×400px）。
- 操作：画像の中央を追加指定。通常のReact画面へ画像を読み込み、合成ポインターイベントで指定した。
- 小さい入力の比較では、同じ画像を再構成用のAPIに渡して推論時間を測定した。

| 設定 | 測定対象 | 回数 | 結果 |
|---|---|---|---|
| CPU・600×400 | 指定完了からマスク表示まで | 4 | 4,955 / 4,620 / 4,909 / 4,678ms |
| CPU・600×400 | 上記に含まれる`segment()` | 4 | 4,930 / 4,598 / 4,887 / 4,667ms |
| CPU・長辺384 | `segment()` | 2 | 5,122 / 4,851ms |
| CPU・長辺256 | `segment()` | 2 | 4,900 / 4,596ms |
| CPU・長辺128 | `segment()` | 2 | 4,769 / 4,738ms |
| GPU・600×400 | マスクの成立 | 1 | CPUで選択できた同じ位置で、二値化後のマスクが空になった |

これは1画像・1環境での検証であり、利用者のすべての写真や端末の性能を保証するものではない。

## 判断

1. 1,500ms目標は未達成。
2. 時間の大部分はMediaPipeの`segment()`にあり、マスク変換・色付け・重ね描きの最適化だけでは不足する。
3. この環境では入力を縮小しても推論時間がほぼ変わらず、画質を下げる設定は採用しない。
4. GPU指定では正しいマスクを確認できなかったため、GPU優先の試験変更は取り除き、既存のCPU設定を維持する。GPU内部の不具合の原因は未特定。
5. Worker化は操作中の画面停止を防ぐ候補になるが、推論自体を1,500ms以内にする根拠にはならない。

## 次に必要な検証

- 実際に使用する写真と通常のブラウザ画面で同じ計測をする。
- MediaPipeのGPU経路で空マスクになる原因を、モデル・Wasm・ライブラリの組み合わせを含めて調べる。
- GPU経路が成立しない場合、対応モデルや推論実装の変更を別Issueで検討する。依存パッケージ追加や領域指定の仕様変更は、プロジェクトの規約に従って確認してから行う。

公式資料：[Interactive image segmentation guide for web](https://developers.google.com/edge/mediapipe/solutions/vision/interactive_segmenter/web_js)。CPU/GPUの指定とWorkerの説明はあるが、本プロジェクトでの1,500ms達成を保証するものではない。

## 2026-09-30のVisual Hull再測定

`/dev/visual-hull`の4枚のマイク写真では、正面の指定完了からMaskサムネイル表示まで4,782msで、内訳はモデル準備493ms、`setImage()`5ms、`segment()`4,252ms、表示26msだった。1,500ms目標は未達。右4,092ms、背面8,127ms（候補2回）、左4,136ms。候補探索はそれぞれ31/22/23ms、サムネイル表示は26/36/32msだった。推論はWorker内でも同期で、時間の大半を占める。4方向1回ずつの観測であり分布の推定ではない。CPU/GPU比較はGPU初期化時の`ModuleFactory not set.`で成立せず、CPUを継続する。詳細は`07-visual-hull-evaluation.md`を参照。
