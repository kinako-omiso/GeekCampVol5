# Issue #35：本番UIへの撮影・解析・対戦統合

## 概要

本番フローで使うPC画面はロビー、スキャン進捗、対戦、結果とする。`/dev` のマスク生成・モデル生成・向き／高さ調整画面は使わない。生成と解析はPCの裏側で実行し、配置は既存の初期値で自動決定する。

## 実装

- 本番のスマホ撮影UIで4枚撮影し、一覧から正面を選ぶ。正面画像の対象指定を「ぬる／けす」のストローク操作にする。残り3枚は撮影順に右・背面・左へ割り当てる。
- スマホから写真4枚と正面選択・ストロークをPCへ送る。PCで既存のマスクWorkerにより4方向のマスクを生成し、結果をスマホへ返す。スマホで確認・修正したストロークはPCへ送り、該当方向だけ再計算する。
- マスク確定後、PCで既存のVisual HullとC++形状解析を実行する。`createDefaultPlacement` と既存のモデル準備処理で2体を自動配置する。配置できない場合はスキャン進捗画面に理由を表示し、対象プレイヤーの撮り直しへ戻す。
- 本番のPC対戦画面に既存のBabylon物理エンジンとHUDを組み込む。`/dev` のキーボード操作や検証表示は使わない。スマホの傾きとA/B、能力値、HP、60秒、場外・時間切れ・引き分けを接続する。
- PCを画面進行の管理元とし、モックの画面送りを実際の状態に置き換える。通信断では試合を停止し、再接続後3秒で再開する。結果からPC操作でロビーへ戻る。

## 通信と検証

- 現行PeerJSのcontrol・motion・assetチャネルと、写真のチャンク転送・受信確認・ハッシュ検証を維持する。4枚の識別、ストローク、画面状態に必要な型だけ共有プロトコルへ追加する。スマホへのマスク返送は既存assetチャネルを逆方向にも使い、新しい通信方式は作らない。
- 正面選択と方向割当、ストロークによるマスク生成・修正、転送失敗時の再送、2人分の自動配置、対戦の各決着条件、通信断からの復帰を確認する。既存の `/dev` 検証ページも動作を保つ。
- lint・型チェック・ビルドと関連テストを通し、iOSとAndroidの実機2台およびVercel Previewで通し動作を確認する。

## 前提

- PCのマスク生成・モデル生成・配置調整画面、および `PhysicsBattleTest` の検証用UIは本番で表示しない。再利用するのは処理ロジックと物理エンジン。
- 撮影は4枚固定。#49 の自動倍率と現行の暫定能力値を使う。斜め方向、登場演出、スマホの向き調整、再戦の2択は本番フローに含めない。
- 確定した操作と処理分担を仕様文書へ反映する。新しい依存パッケージは追加しない。
