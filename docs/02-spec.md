# 仕様書：ゲーム設計
本書の数値は全て初期値であり、実装後に実際に遊んで調節する。

## アリーナ
コマは正規化により最長軸が1.0。以下の距離はすべてこの単位で表す。

| 項目 | 値 | 根拠 |
|---|---|---|
| リング半径 | **6.0** | コマの最長軸の6倍。広すぎると近づくだけで60秒が終わる |
| 初期配置 | 対面、中心から**各3.0**（半径の50%） | 両者の距離は 6.0 |
| 移動速度の基準 | **3.0 units/秒**（倍率1.0のとき） | 直径12.0 を約4秒で横断できる |
| 実際の移動速度 | 2.4 〜 3.75 units/秒 | 移動速度倍率 0.80〜1.25 を掛けたもの |

### リング縮小
時間経過でアリーナの有効半径を縮める。目的は逃げ切りを最適解としないため

| 時刻 | 動き | 半径 |
|---|---|---|
| 0〜25秒 | 通常戦 | 6.0（100%） |
| 25秒 | 予告3秒 → 縮小 | 4.2（70%） |
| 45秒 | 予告3秒 → 縮小 | 2.7（45%） |
| 60秒 | 時間切れ | — |

- 必ず段階的に、予告付きで縮める
- 予告は境界の点滅と効果音で表す

実装は物理形状を作り直さず、衝突フィルタで処理。床は固定サイズのまま置き「減愛の有効半径」を数値として別に持つ。中心からの距離がそれを超えたコマだけ、床の子リジョンマスクを外して落とす。視覚上の半径と物理判定は必ず数値を参照する。

## 戦闘設計
- 勝敗はHP制
- 攻撃は体当たり小と体当たり中の2種類（ボタン2つに直接割り当て）
- 接触ダメージはなし

### 攻撃

| 攻撃 | 入力 | 予備動作 | 最小間隔 / クールダウン | 到達距離 | 基本ダメージ |
|---|---|---|---|---|---|
| 体当たり小 | Aボタン | なし | 最小間隔 0.4秒 | 1.2 | 3 |
| 体当たり中 | Bボタン | 0.3秒 | クールダウン 3秒 | 2.4 | 18 |

- 実ダメージ ＝ 基本ダメージ × 攻撃力倍率
- 実到達距離 ＝ 到達距離 × リーチ倍率
- 体当たり小の「最小間隔」とはモーションの長さのこと。連打を物理的に不可能にするためのもの

### 予備動作
体当たり中に予備動作をもたせる。**コマが後ろに引く**。溜めて放つ動き。引いた距離がそのまま「今から体当たり中がくる」という情報になる。
- 引く距離は0.3程度
- 0.3秒かけて引き、放つ瞬間に前方に加速する
- 足元のプレイヤーカラーリングを一瞬強く光らせる

### 被弾のフィードバック
2人が同じ画面を見ているため、HPバーだけでは自分が被弾したのか分かりにくい。
よって追加で3つ実装する

| 手段 | 内容 |
|---|---|
| ヒットストップ | 命中の瞬間に 0.05秒だけ時間を止める |
| 白点滅 | 被弾したコマを 0.1秒間 白く点滅させる |
| 振動 | 被弾した側のスマホを振動させる |

### 押し出し
剛体同士の衝突なので、突進で当たれば物理エンジンが自動的に押し合いを起こす。明示的なノックバックを咥える衝突イベントで`applyImpulse`を呼ぶ

### プレイヤーの識別
コマの足元にプレイヤーカラーのリングを敷く

| プレイヤー | 色 |
|---|---|
| Player 1 | 青 |
| Player 2 | 赤 |

- コマ自体には着色しない。スキャンした見た目を損なうため。
- 同じ色をHPバー、スマホ画面の背景、登場演出の枠にも使い、どこを見ても自分の色が同じであるようにする

### 勝敗条件
- HPが0になった瞬間
- リング外へ押し出された瞬間
- 制限時間は60秒
- 時間切れの場合、残りHPが多い側の勝ち、同じなら引き分け

## 操作設計
入力は**傾けとボタンの2系統だけ**。振り検出もチャージの長押しも使わない。
 
| スマホ側の入力 | ゲーム内の振る舞い | 送信 |
|---|---|---|
| 端末の傾き（beta / gamma） | コマの向きと移動 | 30Hzの連続送信 |
| Aボタン | 体当たり小 | イベント |
| Bボタン | 体当たり中 | イベント |
| 決定ボタン（メニュー中のみ） | 向きの確定・準備完了 | イベント |
 
ボタンを押した瞬間に種別を送るだけなので、遅延が操作体験に与える影響が最小になる。チャージ式なら溜め量をPC画面に2人分表示する必要があったが、それも不要。
 
画面上のボタンは常に2つ。対戦中はAとB、メニュー中は決定に切り替える。
 
プレイヤーはスマホを見ずにPC画面を見るので、手元を見なくても押せる大きさが要る。画面下半分を二分割する程度。

### センサーの初期化
 
1. 接続後、「センサーを有効化」ボタンからモーション権限を要求する
2. 1秒間静止して基準姿勢を取得する
3. 以降は `beta` と `gamma` の差分だけを使う
4. 横持ち固定、有効範囲は ±60度
5. スマホ側で符号・向き・デッドゾーンを正規化し、`-1〜1` の移動ベクトルとして送る
絶対方位（`alpha`）は徐々にずれるため使わない。
 
### 触覚フィードバック
 
- Android：命中30ms、被弾60ms、敗北 `[60, 40, 120]`
- iPhone：コントローラー画面のフラッシュと短い効果音
- 振動API非対応時は自動でiPhoneと同じ代替処理へ切り替える

## 音響設計
 
効果音を入れる

| 場面 | 音 |
|---|---|
| 命中 | 短い打撃音（小と中で音程を変える） |
| 場外 | 落下音 |
| リング縮小の予告 | 警告音（3秒間） |
| 残り10秒 | カウントダウン |
| 決着 | 決着音 |
 
すべて短い単発音にする。

## スキャンフロー

### Issue #2：Quick ScanのPC検証

1. PCの /dev/photo-model で写真ファイルを1枚選ぶ。Maskファイルを直接入力する画面は設けない。
2. MediaPipe Interactive Segmenterで対象物を指定し、Maskを重ねて確認する。追加・除外の指定とやり直しができる。
3. 最大連結成分を残し、内部の穴を埋め、外周をRDP 0.2%で単純化する。輪郭の最長軸を1.0にそろえる。
4. 輪郭をZ方向へ最長軸の25%だけ押し出す。positions / indices / normals を生成し、Babylon.jsで #dddddd の単色Materialとして360°確認する。検証画面ではモデルの体積重心を回転軸にしてドラッグでモデルを回し、ホイールでモデルを拡大縮小する。カメラと光源は固定する。

この段階では写真テクスチャとUVを作らない。Maskは再構成関数の内部入力および合成Maskによるテストに使う。PCとスマホの転送、geometry-wasm での形状解析、対戦画面への組み込みは後続の段階で行う。

### 将来拡張：実3Dモード
 
Polycam / Scaniverse で書き出した GLB を読み込む方式。**初期版には含めない。**
 
含めない理由：
 
- 外部アプリへの依存が増える。デモで「事前にスキャンしておく」前提が必要になる
- 10MB のファイル転送が要り、チャンク分割・進捗・ハッシュ検証の実装が重くなる（写真は 0.5〜1.5MB）
- **3D凸包（QuickHull）の実装が必要になる**。写真モードだけなら2D凸包で足りる（1.6 節）
- モード選択のUIが増える
追加する場合は、能力値の基準テーブルを GLB 由来のサンプルも含めて作り直し、算出式のバージョン番号を上げること。**写真と GLB で別の補正値は入れない**という原則は維持する。

## カメラ
 
**対戦画面は1台のPC画面を2人で共有する。画面分割はしない。**
 
### 仕様
 
- 斜め俯瞰。仰角は 45〜55度
- 常に2コマの中点を注視点とする
- 2コマの距離に応じてズーム。倍率の変化幅は **1.0〜1.3倍**に抑える
- **カメラの方位角（yaw）は固定。絶対に回転させない**
- プレイヤーはカメラを操作できない
Babylon.js では `ArcRotateCamera` の `alpha` と `beta` を固定し、`target` と `radius` だけを毎フレーム補間する。

### 画面分割
 
対戦画面は分割しない。
 
| | 共有1画面 | 分割2画面 |
|---|---|---|
| カメラ | 1つ | 2つ |
| 描画負荷 | 1回 | 2回 |
| コマの見た目の大きさ | 画面いっぱい | 画面半分 |
| 位置関係の把握 | 常に両者が見える | 相手が画面外に消える |
 
**向き調整画面は分割する**各プレイヤーが自分のコマだけを見て回す場面
 
### カメラのスマホ操作について

カメラのスマホ操作は行わない。2人が同じ画面を見るため、別々のカメラ操作が原理的に成立しない。

## 演出設計
 
試合中にコマを大写しにする必要はない。必要なのは**「スキャンした物が自分のそれだと分かる瞬間」**であり、それは演出で作る。
 
| 場面 | 見せ方 |
|---|---|
| 登場演出 | 試合前、コマが回転しながらせり上がる。大写しで能力値を表示する |
| 結果画面 | 勝ったコマをアップで映す |
| 試合中 | 斜め俯瞰で立体感を残す。影とライティングで形を立たせる |
 
**登場演出がこの作品の見せ場**であり、デモ動画で一番効く絵になる。試合中の画ではない。
 
この位置づけを決めておかないと、実装中に「試合中もっと寄せたい」という揺り戻しが起きる。試合中のカメラは**読みやすさを優先し、見栄えは登場演出で回収する**。

## 中断と再戦
 
###  試合中の切断
 
**一時停止して再接続を待つ。**
 
- 切断を検知したら物理ステップとタイマーを止める
- 「Player N の接続が切れました」と表示し、再接続用のQRを再表示する
- 再接続後、3秒のカウントダウンを挟んで再開する
そのまま続行すると切断された側のコマが棒立ちになり、即敗北にするとデモ中の一度の通信断で試合が終わる。
 
### 再戦
 
結果画面から**2つの選択肢を出す**。
 
| 選択肢 | 動作 |
|---|---|
| 同じコマでもう一度 | スキャンを省略し、登場演出から再開 |
| コマをスキャン直す | スキャンフローの最初へ戻る |

## 画面構成
 
**PC（/host）**
 
| 画面 | 内容 |
|---|---|
| ロビー | QRコード2つ、接続状態、両プレイヤーの準備状況 |
| スキャン | 両プレイヤーの進捗（転送・解析）。直列処理中は待機表示 |
| 向き調整 | **左右分割**。各自のモデルと能力値。確定側は暗転＋「準備完了！！」 |
| 登場演出 | 両者のコマを順に大写しし、能力値を提示 |
| 対戦 | アリーナ、両者のHPバー、残り時間、リング縮小の予告 |
| 結果 | 勝敗と最終HP、勝ったコマのアップ、再戦の2択 |
 
**スマホ（/controller）**
 
| 画面 | 内容 |
|---|---|
| 接続 | センサー有効化ボタン、基準姿勢の取得 |
| スキャン | 撮影、領域指定、転送の進捗、やり直しボタン、プリセット選択 |
| 向き調整 | 傾けで回転、決定ボタンで確定 |
| 対戦 | AボタンとBボタン、接続状態 |
 
スマホ画面の背景色はプレイヤーカラー（4節）に合わせる。
